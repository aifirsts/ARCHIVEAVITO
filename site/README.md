# Beauty Supply — архивная витрина (новый сайт)

Публичный сайт магазина **Beauty Supply**: 14 объявлений Avito, собранных из проверенных архивов.
Сайт **не принимает оплату**, не обещает доставку и не подтверждает наличие: все цены помечены как
архивный снимок 26.10.2026, кнопка ведёт на конкретное объявление Avito.

## Что внутри

| Путь | Назначение |
| --- | --- |
| `site/src/site.css` | дизайн-система (типографика, сетки, состояния загрузки/ошибки, адаптив) |
| `site/src/app.js` | галерея с клавиатурой и лайтбоксом, поиск, фильтры, сортировка, состояния изображений |
| `site/build.py` | генератор сайта из `handoff/storefront.json` в `site/public` |
| `site/public/` | **готовый статический сайт** (единственный веб-корень) |
| `site/tests/browser_smoke.py` | smoke-тест в настоящем Chromium: десктоп 1440×950 и мобильный 390×844 |

Тяжёлые PNG из нового архива (5 кадров галереи + фото из PDF-печати) перекодируются в JPEG q82: это уменьшает
публичный каталог с 12 МБ до 7 МБ. В `assets/images.json` у каждого файла указаны `source_path`, `source_sha256`,
`transform` и `published_sha256`, поэтому опубликованный JPEG прослеживается до исходного PNG с точным хешем.

Публикуется только `site/public`: в нём нет исследовательских JSON, отзывов, исходных ZIP, HTML и скриптов архивов.
Перечень опубликованных изображений с SHA-256 и путём-источником — `site/public/assets/images.json`.

## Сборка и просмотр

```bash
python -m pip install -r requirements-dev.txt   # Pillow нужен для перекодирования PNG → JPEG
python handoff/generate.py            # обновить пакет данных (детерминированно)
python site/build.py                  # пересобрать site/public
python site/build.py --check          # проверить, что сохранённая сборка совпадает с источниками
cd site/public && python -m http.server 8080 --bind 0.0.0.0
```

Откройте `http://localhost:8080/`. Сайт полностью статический: относительные пути работают и в подпапке.

## Проверки

```bash
python -m unittest discover -s tests -v          # 37 офлайн-тестов: архив, пакет данных, сборка, ссылки, хеши
node --check site/src/app.js
python -m pip install playwright && python -m playwright install chromium
python site/tests/browser_smoke.py               # ~40 проверок в браузере, 0 ошибок консоли
```

CI (`.github/workflows/validate.yml`) прогоняет офлайн-тесты, проверяет детерминированность пакета и сборки
(`git diff --exit-code -- site/public`), собирает сайт как артефакт и отдельным job запускает браузерный тест.

## Публикация

В репозитории GitHub Pages **не включён** (в момент сборки `GET /repos/aifirsts/MATRIX2/pages` возвращал 404, а токен
сессии не даёт менять настройки). Артефакт `beauty-supply-site` из CI — это готовый к публикации каталог.
Чтобы включить Pages: *Settings → Pages → Source: GitHub Actions*, затем добавить job деплоя
(`actions/upload-pages-artifact` + `actions/deploy-pages` с `path: site/public`). Домен и публичный адрес в этой
сессии не настраивались — не считать сайт развёрнутым.

## Что важно знать о данных

- **Источник истины:** `handoff/storefront.json` (генерируется из `catalog.json`, `avito_audit/*` и
  `official_assets/manifest.json`). Сайт ничего не придумывает: отсутствующие фото показаны как отсутствующие.
- **Три слоя, которые нельзя смешивать:** фото объявления/профиля из архивных HTML, новый датированный слой
  25.10.2026 (`Attachments-Avitos.zip`: мобильные скриншоты галереи и PDF-печати страниц) и материалы
  производителей (иллюстрации и описания линеек).
- **Известные пропуски:** у часов `8296456393` нет файла позиции № 9 (страница показывает 9 кадров, в архиве 1–8);
  у лота `8350792227` есть только фото упаковки одного чехла — второй чехол лота «2 шт» не сфотографирован,
  отдельной HTML-карточки нет. Подробности: `avito_audit/ATTACHMENTS_2026_10_25.md`.
- **Права:** иллюстрации брендов принадлежат правообладателям; владение магазином не означает разрешение на их
  коммерческое использование. Перед коммерческим запуском это нужно согласовать.
- **Отзывы и личные данные** из исходного HTML не публикуются.
